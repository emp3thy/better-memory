# Better-Memory UI — Data-Source Inventory

A per-feature map of every data access the management UI performs: which route/fragment
drives it, what tables it touches, whether it goes through a service, and — critically —
whether it flows through the `StorageBackend` abstraction or hits local sqlite directly.

## Architecture: how the UI reaches its data

The UI (`better_memory/ui/app.py`) is **backend-unaware**. At `create_app()` it opens the
**local `memory.db`** directly as a `sqlite3.Connection` (WAL, `foreign_keys=ON`, sqlite-vec,
`Row` factory) and stores it in `app.extensions['db_connection']` — regardless of
`config.storage_backend`. It never imports `storage/factory.py`, `build_backend`,
`resolve_storage_backend`, or any `StorageBackend`.

The data flow splits into three lanes, and **none of them cross the `StorageBackend` Protocol**:

- **Reads → `queries.py` (raw SQL).** List panels, drawers, and dropdown population run
  parameterized `SELECT`s from `queries.py` (or inline in a route) directly on the shared
  `sqlite3.Connection`. They bypass `StorageBackend` entirely.
- **Writes → service layer (raw SQL).** `EpisodeService`, `ReflectionService`, and
  `SemanticMemoryService` receive the **raw `sqlite3.Connection`**, not a `StorageBackend`
  object. They mutate local sqlite (often inside a `SAVEPOINT`), so even UI *writes* bypass
  the backend abstraction.
- **A few writes hit sqlite inline.** Hook-error delete/purge run `conn.execute` +
  `conn.commit()` straight in the route, with no service and no `queries.py`.

### The agentcore parity risk

In agentcore mode the **memory-content** tables (`observations`, `reflections`,
`semantic_memories`, `episodes`, and their embeddings) live **AWS-side** under
`AgentCoreBackend`. Because the UI opens local sqlite unconditionally, any read/write of those
content tables would see **nothing** (empty/partial content) in agentcore mode. By contrast,
**operational-state** tables (`session_memory_exposure`, `audit_log`, `hook_errors`,
`retention_runs`, `rating_diagnostics`) **always stay local** and remain correct in either mode.
Additional gaps: the Episodes tab is meant to be hidden when `supports_episodes=False`
(agentcore), but **no capability gating exists** in the UI today.

> **In this inventory, `goes_through_backend = false` for every single item.** The
> distinction that matters is not backend-vs-not (nothing uses the backend) but
> **content-table vs operational-state**: the former is the agentcore risk surface, the
> latter is safe.

## TOP SUMMARY — the agentcore risk surface

Every read below **bypasses `StorageBackend`**. The ones that touch **content tables** are
the agentcore-parity risk (they would return empty/NULL against AWS-side records); the ones
touching only **operational-state** tables are safe in agentcore mode.

### Reads that bypass the backend AND touch content tables (agentcore RISK)

| Domain | Feature | Content tables |
|--------|---------|----------------|
| Observations | Project dropdown population | `observations` |
| Observations | List panel (filtered, day-grouped) | `observations` |
| Observations | Detail drawer (content portion) | `observations`, `reflections`, `reflection_sources` (+ local `audit_log`) |
| Reflections | Project dropdown population | `reflections` |
| Reflections | List panel | `reflections` |
| Reflections | Detail drawer (row + provenance) | `reflections`, `reflection_sources`, `observations`, `episodes` |
| Reflections | Edit form pre-populate | `reflections`, `reflection_sources`, `observations`, `episodes` |
| Episodes | Timeline (day-grouped list) | `episodes`, `observations`, `reflection_sources` |
| Episodes | Unclosed-episode banner | `episodes` |
| Episodes | Detail drawer | `episodes`, `observations`, `reflections`, `reflection_sources` |
| Episodes | Close pre-check (guard read) | `episodes`, `observations`, `reflections`, `reflection_sources` |
| Semantic | List/filter/search panel | `semantic_memories` (+ local exposure/diagnostics) |
| Semantic | Detail drawer (row) | `semantic_memories` (+ local exposure) |
| Diagnostics | Recent ratings table (LEFT JOIN to titles) | `reflections`, `semantic_memories` (+ local exposure) |
| Diagnostics | Overlooked total aggregate | `reflections`, `semantic_memories` |
| UI infra | sqlite connection acquisition (opens local db) | — (root cause of all above) |

> The Episodes-tab content reads are **moot in agentcore mode** because the tab should be
> hidden (`supports_episodes=False`) — but the gating is not yet implemented.

### Reads that bypass the backend but touch ONLY operational state (SAFE in agentcore)

| Domain | Feature | Operational tables |
|--------|---------|--------------------|
| Reflections | Rating evidence receipts | `session_memory_exposure` |
| Diagnostics | Rating diagnostics counters | `rating_diagnostics` |
| Diagnostics | Hook errors panel | `hook_errors` |
| Diagnostics | Hook error detail drawer | `hook_errors` |
| Diagnostics | Retention runs panel | `retention_runs` |
| UI infra | Project scoping / resolution (cwd/env, no table) | — |
| UI infra | Session identity resolution (absent in UI) | — |
| UI infra | Left-rail tab navigation (static Jinja) | — |

**Writes** likewise bypass the backend: content writes (`observation → semantic` promote,
all reflection state changes, all semantic CRUD, episode close, write-path service
instantiation) go straight to local sqlite via the service layer — the core agentcore parity
gap — while operational-state writes (hook-error delete/purge) are correctly local-only.
